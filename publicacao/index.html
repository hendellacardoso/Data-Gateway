Como funciona

Um intermediário seguro entre seus sistemas e o banco

Quem consome a API nunca acessa o banco diretamente: só enxerga as tabelas, os campos e as operações que você liberou. O Data Gateway recebe a requisição, confere o token e as permissões, monta o SQL parametrizado e devolve JSON.

Como usar

Guia passo a passo

Do primeiro acesso à API publicada na internet. Clique em cada etapa.

Primeiro acesso

  1. Instale o Data Gateway (ou use a versão portátil, sem instalação) em um computador ou servidor Windows que enxergue o banco de dados.
  2. Na primeira abertura, crie o usuário administrador do painel. A senha é guardada com hash scrypt.
  3. O servidor da API já sobe sozinho em http://localhost:8787. O indicador verde no topo e a barra de status mostram se ele está no ar.
  4. Em Sistema → Configurações você pode trocar a porta, ativar o início junto com o Windows e manter o programa na bandeja ao fechar a janela.

Dica: instale no mesmo servidor do banco ou em uma máquina da mesma rede — assim o banco não precisa ficar exposto.

Conectar o banco

  1. Abra Conexões → Bancos → Nova conexão e escolha o tipo: SQL Server, PostgreSQL, MySQL, MariaDB, Firebird ou SQLite.
  2. Informe servidor, porta, banco, usuário e senha. No SQLite, selecione o arquivo. No Firebird, informe o caminho do .FDB como o servidor enxerga (ex.: C:\Sistema\Dados\SISTEMA.FDB) ou o alias.
  3. Clique em Testar conexão: aparecem a versão do banco e o tempo de resposta.
  4. Salve. A senha do banco fica criptografada pelo Windows (DPAPI).

Para relatórios e consultas, prefira um usuário de banco somente leitura.

Criar a API (assistente em 13 passos)

  1. Em APIs → Endpoints → Nova API, escolha o banco e a tabela (ou view).
  2. Defina o endereço, por exemplo clientes → /api/v1/clientes.
  3. Campos: marque quais aparecem, o tipo lógico (texto, inteiro, decimal, data, booleano…), o nome na API e os obrigatórios.
  4. Consulta e filtros: paginação padrão e máxima e quais filtros a API aceita (ex.: nome contém, cidade igual).
  5. Ordenação, inclusão, alteração e exclusão: o que pode ser ordenado, quais campos podem ser gravados e se a exclusão é física ou lógica.
  6. Upload (opcional), permissões, revisão e Publicar.

O SQL é gerado automaticamente e sempre parametrizado — nada do que chega na requisição vira texto SQL.

Tokens e permissões

  1. Em APIs → Tokens, crie um token para cada sistema que vai consumir a API (ex.: “App de vendas”, “Power BI”).
  2. Defina validade (opcional) e marque, por endpoint, o que o token pode fazer: consultar, buscar por ID, incluir, alterar, excluir, enviar arquivos.
  3. Copie o token na hora: ele é exibido uma única vez. Depois só fica guardado o hash.
  4. O token vai sempre no cabeçalho Authorization: Bearer <token> — nunca na URL.

Token vazou? Revogue e gere outro em segundos, sem afetar os demais sistemas.

Testar e documentar

  1. Abra APIs → Testador de API, escolha o endpoint, cole o token e clique em Enviar.
  2. Veja o status, o tempo e o JSON de resposta. Funciona para GET, POST, PUT, PATCH, DELETE e upload.
  3. Em APIs → Documentação, abra o Swagger (/docs) ou baixe o openapi.json para entregar a quem vai integrar.

O Swagger é gerado da configuração: mudou um campo ou filtro, a documentação já está atualizada.

Consultas SQL personalizadas

  1. Em APIs → Consultas SQL → Nova consulta, monte o SELECT no diagrama (as ligações aparecem pelas chaves estrangeiras) ou escreva no editor SQL.
  2. Use parâmetros nomeados como :codigo ou :desde, informe o tipo e um valor de teste.
  3. Executar (Ctrl+Enter) mostra o resultado, com exportação CSV/JSON.
  4. Em Publicação, defina o endereço e os tokens: a consulta vira GET /api/v1/consultas/<endereço>.

Só SELECT/WITH são aceitos, em transação somente leitura — o banco recusa qualquer escrita.

Publicar na rede ou na internet

  1. Rede local: libere a porta da API (padrão 8787) no Firewall do Windows. Os outros computadores acessam http://IP-DO-SERVIDOR:8787/api/v1/….
  2. Internet: coloque um proxy com HTTPS na frente (Caddy, Nginx ou IIS) apontando para a porta da API, com um domínio próprio (ex.: api.suaempresa.com.br).
  3. Ajuste em Sistema → Configurações o CORS (sites que podem chamar a API pelo navegador), o limite de requisições por minuto e o tempo limite das consultas.

Nunca exponha a porta do banco de dados na internet — exponha apenas o Data Gateway, com HTTPS.

Acompanhar o uso

  1. O Dashboard mostra o status do gateway, conexões, requisições e erros do dia e o tempo médio de resposta.
  2. Monitoramento → Logs: cada requisição com método, rota, token, status e tempo.
  3. Monitoramento → Auditoria: logins, mudanças de configuração, tokens e alterações de dados.
  4. Em Sistema → Configurações, exporte um backup da configuração antes de mudanças grandes ou ao trocar de servidor.

Como consumir a API

Todas as rotas ficam em /api/v1, recebem e devolvem JSON e exigem o cabeçalho Authorization: Bearer <token>.

OperaçãoRota
Listar (paginado)GET /api/v1/{endpoint}
Buscar por IDGET /api/v1/{endpoint}/{id}
IncluirPOST /api/v1/{endpoint}
Alterar tudo / partePUT · PATCH /api/v1/{endpoint}/{id}
ExcluirDELETE /api/v1/{endpoint}/{id}
Enviar arquivosPOST /api/v1/{endpoint}/{id}/arquivos
Consulta SQL publicadaGET /api/v1/consultas/{endereço}
DocumentaçãoGET /docs · /openapi.json

Parâmetros de listagem

page, pageSizePágina e quantidade por página (até o máximo do endpoint).
sort, directionCampo de ordenação e asc/desc.
expandInclui dados relacionados (ex.: ?expand=itens).
filtrosOs nomes configurados no endpoint (ex.: ?nome=silva&cidade=Goiânia). Parâmetros desconhecidos são recusados.

  --data-urlencode "cidade=Goiânia" -d sort=nome -d pageSize=20 \
  -H "Authorization: Bearer SEU_TOKEN"

Segurança

Seu banco continua fechado. A API só faz o que você liberou.

O Data Gateway não executa SQL enviado por quem chama a API. Tabelas, campos, filtros e ordenações vêm de uma lista autorizada e todo valor recebido vira parâmetro.

  • Whitelist de tabelas, campos, operadores e ordenações
  • Consultas 100% parametrizadas (sem SQL injection)
  • Token só no cabeçalho Authorization: Bearer
  • Rate limit por token e tempo limite de consultas
  • Senhas do painel com scrypt; tokens guardados como SHA-256
  • Senhas dos bancos protegidas pelo Windows (DPAPI)
  • Consultas SQL publicadas em modo somente leitura
  • Erros sem stack trace nem mensagens internas do banco

RedeAcesso ao servidor do banco de dados
Preciso saber programar?

Não para publicar a API: tudo é feito em telas. Para consumir a API, use a ferramenta de sua preferência (app, site, Power BI, n8n…). Conhecer SQL ajuda apenas no recurso opcional de Consultas SQL.

Quais bancos são suportados?

Microsoft SQL Server, PostgreSQL, MySQL, MariaDB, Firebird (2.5 a 5.0) e SQLite. É possível ter várias conexões ao mesmo tempo, inclusive de tipos diferentes.

Meus dados passam por algum servidor externo?

Não. O Data Gateway roda no seu computador ou servidor e conversa diretamente com o seu banco. As configurações ficam em um banco SQLite local, em %APPDATA%\Data Gateway.

Ele altera a estrutura do meu banco?

Não. Ele só lê a estrutura (tabelas, colunas, chaves) e executa as operações de dados que você liberar em cada endpoint. Nenhuma tabela é criada ou alterada no seu banco.

Funciona com o Firebird do meu sistema Delphi?

Sim. Firebird 2.5, 3.0, 4.0 e 5.0, dialeto 1 e 3, inclusive bancos com charset NONE/WIN1252. Informe o servidor, a porta 3050 e o caminho do arquivo .FDB. Não é preciso instalar o fbclient.dll.

Como acesso a API de fora da minha rede?

Coloque um proxy reverso com HTTPS (Caddy, Nginx ou IIS) apontando para a porta do Data Gateway (padrão 8787) e use um domínio. Não exponha a porta do banco de dados.

Ele precisa ficar aberto?

Ele fica na bandeja do Windows e pode iniciar junto com o sistema. Com a opção de minimizar para a bandeja ativa, fechar a janela não derruba a API; para encerrar, use Sair no ícone da bandeja.

Como atualizo para uma versão nova?

Instale a versão nova por cima — as configurações são mantidas. Na versão portátil, basta substituir o executável. Recomenda-se exportar um backup antes (Sistema → Configurações).

O programa é assinado digitalmente?

Sim. Os executáveis são compilados a partir do código aberto no GitHub e assinados. Free code signing provided by SignPath.io, certificate by SignPath Foundation — veja a Code signing policy. Nas primeiras semanas de uma versão nova, o SmartScreen ainda pode exibir um aviso; clique em Mais informações → Executar assim mesmo.
