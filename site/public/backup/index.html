Como funciona

Configure uma vez. O backup acontece sozinho.

Você cadastra o servidor, escolhe os bancos e o horário. O API2Dev Backup gera o arquivo com a ferramenta oficial de cada banco, compacta, envia para os destinos e registra tudo no histórico.

Bancos suportados

Cada banco com a sua ferramenta oficial de backup

Os arquivos gerados são os mesmos que um DBA faria à mão — e podem ser restaurados fora do sistema, se precisar.

SQL Server

BACKUP DATABASE gerando .bak com COPY_ONLY e CHECKSUM — não interfere na sua rotina de backups. Express, Standard e Enterprise.

PostgreSQL

pg_dump no formato custom (.backup) e restauração com pg_restore, encerrando as conexões ativas do banco de destino.

MySQL e MariaDB

mysqldump com --single-transaction, rotinas, triggers e eventos. Restaura até com outro nome de banco.

Oracle

Data Pump (expdp/impdp) por schema, com REMAP_SCHEMA para restaurar em outro schema.

Seleção de bancos

Liste os bancos do servidor e marque quais entram em cada tarefa. Uma tarefa pode ter vários bancos.

Defina a quantidade máxima de backups por dia: ao passar do limite, os mais antigos do dia são removidos.

Histórico completo

Segurança

Seus dados não passam por servidores da API2Dev.

O API2Dev Backup roda no seu computador ou servidor. Os arquivos vão direto para a pasta, o Drive ou o FTP que você configurou — e as senhas ficam criptografadas no banco local do aplicativo.

Primeiros passos

Como usar

  1. Instale ou abra o portátil. O aplicativo abre o painel e fica na bandeja do sistema, ao lado do relógio.
  2. Conexões → Nova conexão. Escolha o tipo do banco, informe servidor, porta, usuário e senha e clique em Testar conexão. No SQL Server remoto, informe a pasta de backup do servidor e o caminho de rede para acessá-la (ex.: \\SERVIDOR\Backup).
  3. Tarefas de backup → Nova tarefa. Marque os bancos, os horários e os dias da semana. Ative o ZIP, defina uma senha, a quantidade máxima de backups por dia e por quantos dias guardar.
  4. Configurações. Conecte o Google Drive, informe o FTP e o servidor de e-mail (SMTP) e use os botões de teste.
  5. Execute agora para validar. No Painel, clique em Executar e acompanhe o log em tempo real.
  6. Opcional: serviço do Windows. Em Configurações → Serviço do Windows, clique em Instalar serviço para os backups rodarem mesmo sem usuário logado (disponível no instalador).

Dúvidas frequentes

Perguntas e respostas

Quais bancos são suportados?

Microsoft SQL Server (2012 em diante, inclusive Express), PostgreSQL, MySQL, MariaDB e Oracle (via Data Pump). Você pode ter várias conexões e tarefas ao mesmo tempo, de tipos diferentes.

Preciso instalar alguma ferramenta?

Para SQL Server com usuário e senha, não. Para PostgreSQL, MySQL e Oracle, o computador precisa ter as ferramentas do próprio banco (pg_dump/pg_restore, mysqldump/mysql, expdp/impdp). O sistema procura nas pastas padrão de instalação e você também pode informar o caminho em Configurações → Ferramentas.

O que é a “quantidade máxima de backups por dia”?

É quantas cópias de cada banco ficam guardadas por dia. Se a tarefa roda a cada hora e o limite é 3, ao fazer o 4º backup do dia o mais antigo daquele dia é removido (na pasta local, no Drive e no FTP).

O computador precisa ficar logado?

Não, se você usar o instalador e ativar o serviço do Windows em Configurações → Serviço do Windows. Sem o serviço, os backups rodam pelo aplicativo da bandeja, que inicia junto com o Windows.

Consigo abrir o ZIP fora do sistema?

Sim. O ZIP usa criptografia AES-256 e abre no 7-Zip, WinRAR e similares com a senha definida na tarefa. Guarde essa senha em local seguro.

Como funciona o Google Drive?

Você cria um ID de cliente OAuth do tipo “App para computador” no Google Cloud Console, informa o Client ID e o Client Secret e clica em Conectar conta Google. O sistema cria a pasta de destino e só tem acesso aos arquivos que ele mesmo enviou.

Meu SQL Server está em outro servidor. Funciona?

Sim. O .bak é gravado pelo próprio SQL Server; informe na conexão a pasta de backup do servidor e o caminho de rede para esta máquina acessá-la (ex.: \\SERVIDOR\Backup). A conta do serviço do SQL Server precisa ter permissão de escrita nessa pasta.

Posso restaurar em outro banco, sem sobrescrever o original?

Sim. Na tela de restauração, informe outro nome de banco (ou de schema, no Oracle). Também é possível restaurar em outra conexão do mesmo tipo.

Onde ficam as configurações?

Em um banco SQLite local, em C:\ProgramData\API2Dev\SistemaBackup, junto com os logs. Os backups ficam, por padrão, na subpasta backups — a pasta pode ser alterada.
